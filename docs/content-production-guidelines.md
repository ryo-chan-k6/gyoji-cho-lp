# コンテンツ制作・出典管理ガイドライン

最終更新: 2026-08-15

## 1. 本ドキュメントの目的

Instagramと将来のiOSアプリで利用する、日本の行事・風習・季節体験コンテンツについて、**AIを活用した調査・制作フロー、Fact Check、出典管理、著作権・素材利用、公開時の表示方針**を共通ルールとして定める。

本ガイドラインの目的は、制作速度を高めながら、次を両立することである。

- 情報の正確性
- 日本文化に存在する地域差・諸説への配慮
- 著作権・第三者権利への配慮
- Instagram / iOS双方で再利用できるコンテンツ資産化
- ユーザーからの信頼

法令・Meta・Apple等のプラットフォームルールは変更され得るため、公開・リリース時点の最新公式ルールを再確認する。

---

## 2. Instagramの投稿形式

Instagramは、静止画カルーセルを主軸にせず、**Reels動画を中心に運用する**。

### 基本方針

- 投稿テーマ・Fact Sheet・台本・イラスト等の素材は共通資産として作る
- Instagramでは共通資産を15〜30秒程度のReelsへ編集する
- 将来iOSでは、同じFact Sheetをより詳細な行事コンテンツへ展開する

```text
Content Master
   ├─ Fact Sheet
   ├─ Sources
   ├─ Script / Copy
   └─ Visual Assets
          │
          ├── Instagram Reels
          └── iOS App Content
```

### Reelsで追加する要素

- 冒頭1〜2秒のHook
- ナレーション
- テロップ
- イラスト / モーション
- カット構成
- BGM / 効果音（権利処理済みのものに限る）
- CTA

コンテンツの核は媒体に依存させず、まずContent Masterとして作成する。

## 3. AIを活用した標準制作フロー

投稿テーマのみ人とAIで壁打ちして決め、その後の情報収集・下書き作成はAIを積極的に利用する。

ただし、**AIの記憶や生成結果そのものを根拠にしない**。

### 標準フロー

```text
1. テーマ企画
   人 + AI
        ↓
2. Source Research
   AIが信頼できる情報源を収集
        ↓
3. Fact Sheet作成
   事実・出典・地域差・諸説を整理
        ↓
4. 投稿内容案を複数作成
   Hook / 台本 / CTA等
        ↓
5. 人によるレビュー・選択
        ↓
6. 完成原稿のFact Check
   Fact Sheet / Sourceと再照合
        ↓
7. Reel / iOSコンテンツ制作
        ↓
8. 公開前最終レビュー
        ↓
9. 公開・Source Ledger保存
```

### 人のレビューを必須とする理由

- AIは事実誤認や過度な一般化を行う可能性がある
- 日本文化には地域差・時代差・宗派差・家庭差がある
- 投稿としてのニュアンスが「やらなければならない」に寄り過ぎる可能性がある
- 出典の読み違い・引用範囲の問題を検知する必要がある

公開コンテンツは、原則として人が最終レビューしたもののみとする。

## 4. 情報源の優先順位

AIによる情報収集は、原則として以下の優先順位で行う。

### Priority A: 一次・公的・専門性の高い情報源

- 国・自治体
- 文化庁
- 国立国会図書館
- 国立天文台
- 国立・公立の博物館、美術館、資料館
- 大学・研究機関
- 神社・寺院等の当事者による公式情報
- 行事・文化の専門団体

### Priority B: 信頼できる二次情報

- 専門出版社
- 百科事典
- 大手報道機関
- 信頼できる専門メディア
- 業界団体

### Priority C: 補助情報

- 企業コラム
- 一般Webメディア

### 単独根拠にしないもの

- 個人ブログ
- Instagram / TikTok / X等のSNS投稿
- まとめサイト
- 出典のない記事
- AI回答そのもの

Priority C以下の情報を使う場合は、可能な限りPriority A / Bで裏取りする。

## 5. Fact Sheet

各テーマについて、投稿原稿を作る前にFact Sheetを作成する。

最低限、次の項目を持つ。

| 項目 | 内容 |
|---|---|
| content_id | コンテンツ識別子 |
| topic | テーマ |
| category | 行事 / 風習 / 季節体験 / 育児行事等 |
| key_facts | 公開コンテンツで使用可能な主要事実 |
| fact_confidence | High / Medium / Low |
| regional_variation | 地域差の有無と内容 |
| historical_variation | 時代による違い |
| multiple_theories | 諸説の有無 |
| practical_note | 現代家庭で実践する際の補足 |
| safety_note | 食事・乳幼児・火気等の安全上の注意が必要か |
| sources | 根拠資料一覧 |
| checked_at | 最終確認日 |
| reviewer | 人レビュー担当 |

### 表現ルール

事実の確度に応じて表現を変える。

- High: 「〜です」「一般的に〜します」
- Medium: 「〜とされています」「一般的には〜」
- 諸説あり: 「由来には諸説あります」等を明示
- 地域差あり: 「地域や家庭によって異なります」等を明示

根拠が弱い俗説を、確定した歴史的事実として投稿しない。

## 6. Source Ledger

公開画面にすべての参考資料を表示するかどうかにかかわらず、**内部ではすべての公開コンテンツの出典を追跡できる状態にする**。

Source Ledgerの推奨項目:

| 項目 | 内容 |
|---|---|
| source_id | 出典ID |
| content_id | 対応するContent Master |
| source_name | 資料・ページ名 |
| publisher | 発行主体 |
| source_url | URL |
| source_type | Government / Academic / Official / Media等 |
| accessed_at | 確認日 |
| reliability | High / Medium / Low |
| supported_claims | どの主張の根拠か |
| copyright_note | 引用・転載・画像等の権利注意 |
| notes | 地域差・諸説等 |

AI自身を`source_name`として登録しない。

## 7. Instagramでの出典表示方針

Instagramでは、すべてのReels画面に論文の脚注のような出典を表示することを原則とはしない。

ただし、裏側のSource Ledgerには必ず記録する。

### Level 1: 一般的・安定した事実

例:
- 七夕は7月7日に行われる代表的な年中行事である

方針:
- 投稿画面上の出典表記は原則不要
- Source Ledgerで根拠を管理

### Level 2: 由来・歴史・数字・諸説がある内容

例:
- 七五三の年齢の由来
- 千歳飴の由来
- 特定の風習が始まった時代

方針:
- 「諸説あります」「一般的には」等を適切に表示
- 必要に応じてCaption末尾に「参考: ○○」程度の簡潔な出典情報を付ける
- Source Ledgerでは詳細URLまで保持

### Level 3: 他者の文章・作品を直接引用する場合

方針:
- 原則として直接引用は必要最小限にする
- 引用部分と自分たちの文章を明確に区別する
- 出所を明示する
- 引用要件・利用規約を公開時点で確認する

**「出典を書けば他者の文章・画像を自由に利用できる」という扱いにはしない。**

文化庁は、著作権法上の引用について、出典明記に加え、公表済み著作物であること、公正な慣行、目的上正当な範囲等が必要と説明している。

参考:
- 文化庁「文化芸術活動に関する法的問題についてよくあるご質問」
  - https://www.bunka.go.jp/seisaku/bunka_gyosei/kibankyoka/faq/index.html?s=09
- 文化庁「著作権を学ぶ（教材・講習会）」
  - https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/

## 8. iOSアプリでの出典表示方針

iOSアプリでは、Instagramよりも情報源へ辿りやすい設計を基本とする。

### 推奨UI

各行事・風習詳細画面の末尾等に、次を設置する。

> **参考情報・出典 ＞**

タップ後の例:

```text
参考情報
- 文化庁「○○」
- 国立国会図書館「○○」
- ○○神社「○○」

※行事・風習には地域・家庭・時代による違いがあります。
```

ユーザー体験を妨げない位置に置きつつ、知りたいユーザーは根拠へ到達できるようにする。

Appleは、App Storeアプリについて、デベロッパ自身が作成したコンテンツまたは利用許可を得たコンテンツを使用することを求めているため、第三者素材をアプリへ直接転載する場合は特に権利確認を行う。

参考:
- Apple App Review Guidelines 5.2 Intellectual Property
  - https://developer.apple.com/jp/app-store/review/guidelines/

## 9. 文章と事実の扱い

### 基本ルール

複数の情報源を調査した上で、**公開文章は原則として自分たちの表現で新規作成する**。

例えば、ある公的機関や神社の説明文をそのままコピーして投稿文章にする運用は行わない。

### 事実と表現を分離する

Content Master上では、

```text
Source
  ↓
Fact
  ↓
Own Expression
```

という3段階で管理する。

これにより、情報源の文章そのものと、投稿・アプリ向けに作成した文章を混同しない。

## 10. 画像・動画・音源の権利方針

### 原則

- 自作素材
- 自社で生成したAI素材
- 商用利用可能なライセンスを確認した素材
- Instagram / Apple等が当該用途で利用を認めている公式ライブラリ

を優先する。

### やらないこと

- Webサイトの写真を保存して無断利用する
- 神社・店舗・メディア等の画像を「出典: ○○」だけで転載する
- 他者のイラストをトレース・模倣して利用する
- 権利確認できないBGMを動画へ使用する

文化庁も、第三者が権利を持つ写真・イラスト等について、権利処理済みであることが明示されていない場合は利用者側で確認する必要がある旨を案内している。

参考:
- 文化庁メディア芸術クリエイター育成事業「著作権について」
  - https://creators.j-mediaarts.bunka.go.jp/copyright

## 11. AI生成素材の扱い

### テキスト

AIを調査支援・下書き作成に使用したことだけを理由に、各投稿本文へ「AI生成」と毎回記載する運用は基本ルールとしない。

ただし、Fact Checkと人レビューを必須とする。

### 画像・動画・音声

MetaはAI生成・加工された画像、動画、音声について「AI info」等の透明性表示を運用している。また、写実的なAI動画やリアルに聞こえるAI音声等について開示が必要となる場合がある。

そのため:

- Meta側の最新開示機能・ルールを投稿時に確認する
- 開示対象なら適切に申告する
- 実在の親子の映像に見えるような写実的AI動画より、**明確にイラスト表現と分かるビジュアル**を基本とする
- 実在人物であるかのような誤認を誘う表現を避ける

参考:
- Meta「Our Approach to Labeling AI-Generated Content and Manipulated Media」
  - https://about.fb.com/news/2024/04/metas-approach-to-labeling-ai-generated-content-and-manipulated-media/

Metaのルールは更新頻度が高いため、上記ドキュメント記載を固定仕様とはせず公開時に再確認する。

## 12. 日本文化コンテンツ特有の注意事項

日本の行事・風習は全国一律ではない。

Fact Check時には最低限、次を確認する。

- 地域差
- 宗派・神社仏閣等による違い
- 歴史的変遷
- 現代の家庭で一般化してよい内容か
- 「由来」とされる説明に複数説がないか

### NG例

> 七五三では必ず○○をします。

実際には家庭・地域差がある場合、断定しない。

### 推奨例

> 一般的には○○とされています。地域や家庭によって楽しみ方はさまざまです。

本メディア・アプリの価値観は、文化を「正しくやらせる」ことではなく、**知る機会をつくり、家族で気軽に体験してもらうこと**である。

## 13. Content Masterの推奨項目

InstagramとiOSで同じ調査資産を再利用するため、テーマ単位でContent Masterを持つ。

```yaml
content_id: EVT-001
topic: 十五夜
category: seasonal_event
summary: "..."
key_facts:
  - "..."
regional_variation: "..."
multiple_theories: "..."
safety_note: "..."
sources:
  - source_id: SRC-001
instagram:
  hook_candidates:
    - "..."
  reel_script: "..."
  caption: "..."
  cta: "..."
ios:
  short_description: "..."
  detail: "..."
  how_to_enjoy:
    - "..."
  source_display:
    - "..."
review:
  fact_checked: true
  human_reviewed: true
  reviewed_at: 2026-08-15
```

データ形式自体は実装段階で変更可能だが、**Fact / Source / Instagram表現 / iOS表現を分離して持つ**ことを原則とする。

## 14. 公開前チェックリスト

公開するすべてのInstagram / iOSコンテンツについて、以下を確認する。

- [ ] AI回答だけを根拠にしていない
- [ ] Source Ledgerに根拠を記録した
- [ ] 主要な事実を一次・信頼性の高い情報源で確認した
- [ ] 地域差・諸説の有無を確認した
- [ ] 必要な「一般的には」「諸説あります」等を入れた
- [ ] 他者の文章を不必要にコピーしていない
- [ ] 写真・イラスト・BGM等の利用権限を確認した
- [ ] AI生成メディアについて最新のMeta等の表示ルールを確認した
- [ ] 乳幼児の安全に関わる内容がある場合は安全性を確認した
- [ ] 「やらなければならない」という過度な義務感を生む表現になっていない
- [ ] 人が完成版をレビューした

---

## 15. 制作原則まとめ

> **AIはテーマ企画支援・情報収集・Fact Sheet作成・原稿案作成を担う。AI自身を出典にはしない。公開情報は信頼できるSourceに基づき、人がレビューする。Instagramでは必要に応じて簡潔に出典を表示し、iOSでは参考情報へ辿れる設計とする。調査資産はContent Masterとして共通化し、Instagram ReelsとiOSコンテンツへ展開する。**
