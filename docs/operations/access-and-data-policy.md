# アクセス・秘密情報・データ取扱方針

最終更新：2026年8月17日

## 1. 目的

責任者とAIエージェントが、リポジトリ、外部サービス、ユーザーデータを安全に扱うための最小ルールを定める。

## 2. 情報区分

| 区分 | 例 | リポジトリ | AIへの入力 |
|---|---|---|---|
| Public | 公開LP、公開済み説明 | 可 | 可 |
| Internal | 未公開計画、Task Brief、集計値 | private前提で可 | タスクに必要な範囲で可 |
| Confidential | 未公開契約条件、詳細な収益情報 | 原則保存しない。必要時はアクセス制御された保管先 | 原則不可。匿名化・要約する |
| Personal | 氏名、連絡先、正確な生年月日、インタビュー記録 | 原則保存しない | 実データは不可。匿名化する |
| Secret | APIキー、パスワード、証明書、復旧コード | 禁止 | 禁止 |

GitHubリポジトリが公開か非公開かにかかわらず、Secretと実ユーザーのPersonalデータは保存しない。

## 3. 秘密情報

- APIキー、広告トークン、Apple証明書、署名鍵、パスワード、復旧コードをcommitしない
- ローカル開発では環境変数、OSの資格情報ストア、サービス側のSecrets機能を使う
- `.env.example` にはキー名と説明だけを置き、実値を含めない
- `.env`、証明書、Provisioning Profile、秘密用xcconfigは `.gitignore` 対象とする
- 誤って露出した場合は、削除だけで済ませず、先に資格情報を失効・再発行する
- ログ、画面キャプチャ、Issue、PR、ChatにもSecretを貼らない

## 4. 個人情報と子どもの情報

- テストには架空データまたは統計的に生成したデータを使う
- 正確な生年月日、氏名、住所、連絡先をAnalyticsへ送らない
- 少人数コホートから個人を推測できる集計を外部へ共有しない
- インタビュー記録、録音、謝礼、連絡先は `D-015` とLegal確認後に、目的・期限・削除方法を決めて扱う
- アプリ内プロフィールはLocal-firstを原則とし、外部送信は `D-007`、`D-008` とデータフロー更新なしに追加しない

## 5. 外部サービスと権限

| 操作 | AIが準備できること | 実行条件 |
|---|---|---|
| GitHub push / PR | 差分、commit案、PR本文の準備 | 責任者の明示承認 |
| Cloudflare公開 | 設定、確認手順、変更案 | 責任者の明示承認 |
| 広告配信・課金 | 媒体案、予算案、クリエイティブ | D-ID確定と責任者の実行承認 |
| App Store / Apple契約 | チェックリスト、素材、申請案 | 責任者の明示承認 |
| メール・SNS・ユーザー連絡 | 文案、対象、送信条件 | 送信ごとの責任者承認 |
| 外部SDK追加 | 比較、データフロー、リスク | Data / Legal確認、D-ID、責任者承認 |

権限は最小限・期限付き・個別アカウントを基本とする。共有パスワードを避け、不要になった権限は削除する。

## 6. AIエージェントへの最小開示

- Task Briefに必要なファイルと操作だけを指定する
- 別Workstreamの機密情報を、念のためという理由で渡さない
- 実ユーザーデータの代わりに匿名ID、粗粒度コホート、合成データを使う
- 外部送信やネットワーク利用が必要な場合は、対象ドメインと目的を限定する
- 破壊的操作、公開、課金、契約は `.cursor/agents/` を含むエージェント定義では許可せず、都度承認する

## 7. インシデント初動

秘密情報・個人情報の露出、誤公開、誤配信が疑われる場合は、通常作業を止めて次を行う。

1. 追加露出を止める
2. 資格情報の失効、公開停止など可逆的な封じ込めを行う
3. 何が、いつ、どこへ、どの範囲で露出したか記録する
4. 責任者へ報告し、外部通知や専門家確認の要否を判断する
5. 恒久修正と再発防止をIssue / PRへ残す
