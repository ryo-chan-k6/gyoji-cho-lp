# Decision Record: `D-018 Phase 0の時間枠`

- 状態：Decided
- 決定日：2026-08-16
- 決定者：責任者
- 見直し日：2026-08-23、2026-08-30
- 見直し条件：重大な外部ブロッカー、Frozen Scope変更、週28時間の稼働確保が継続的に困難になった場合
- 置き換える判断：なし

## 決めること

Phase 0の開始日、主要成果物の作成目標、終了期限、前倒しの扱いを固定する。

## 決定

- Phase 0の計画期間を **2026年8月17日〜2026年9月6日の3週間**とする
- 主要成果物の作成目標を **2026年8月30日**とする
- 2026年8月31日〜9月6日は、Workstream横断レビュー、Rework、Phase 0 Gateを中心に使う
- 依存関係と品質Gateを満たす場合、9月6日を待たず前倒しで完了してよい
- 余った時間を理由にFrozen ScopeやPhase 1機能を追加しない

### 週別の重点

| 期間 | 重点 |
|---|---|
| 8月17日〜23日 | `D-001〜005`、対象ユーザー、対象行事、MLPスコープ |
| 8月24日〜30日 | 技術、Analytics、データ、Legal、Validation基準と主要成果物 |
| 8月31日〜9月6日 | 未完了事項、横断レビュー、Rework、Phase 0 Gate、Phase 0.5準備 |

## 背景と制約

責任者は週28時間を本プロジェクトへ確保できる。AIエージェントが調査・草案・整合確認を担い、責任者は判断、レビュー、外部承認へ集中する。この前提では6週間より短い時間枠が妥当だが、5 Workstreamの横断レビューとGateのために3週目を確保する。

## 検討した選択肢

| 選択肢 | 利点 | 欠点・リスク | 採否 |
|---|---|---|---|
| 2週間 | 最短でPhase 0を完了できる | 横断レビューとReworkの余白が小さい | 不採用。ただし前倒し完了は可 |
| 3週間 | 2週間で主要成果物、3週目で品質確保 | 意図的に使わないと期間が膨張する | 採用 |
| 6週間 | 判断と調査の余白が大きい | 週28時間の稼働に対して長く、スコープ膨張を招く | 不採用 |

## 根拠と不確実性

- 根拠：週28時間の責任者稼働、AIエージェント運営、Phase 0のタスクとD-ID構成
- 不確実性：Apple・Analytics・コンテンツ品質の調査で外部確認が必要になる可能性

## 影響

- 影響を受けるTask ID：Phase 0全タスク、`P0-GATE-01`、`P0-GATE-02`
- 更新する正本文書：`phase-0-2-execution-plan.md`、`project-operating-policy.md`
- 新たに生じるリスク：期限を優先してReviewを省略するリスク。品質Gateと3週目の用途固定で抑制する
