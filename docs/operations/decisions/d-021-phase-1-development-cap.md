# Decision Record: `D-021 Phase 1開発上限`

- 状態：Decided
- 決定日：2026-08-16
- 決定者：責任者
- 見直し日：Phase 1の4週目、8週目、または上限超過見込みを検知した時点
- 見直し条件：目標またはハード上限に収まらない見込み、新たな支出・外注・有料サービスが必要になった場合
- 置き換える判断：なし

## 決めること

Phase 1のiOS Validation Release開発について、期間、責任者稼働、追加開発費、上限超過時の扱いを固定する。

## 決定

- 目標を **8週間・責任者224時間** とする
- ハード上限を **10週間・責任者280時間** とする
- 責任者稼働は `D-019` と同じ **週28時間** を基準とする。前倒し完了しても余力を未承認機能の追加へ使わない
- 追加開発費は **0円** とし、既存契約中のAIエージェントサービスと利用可能な無償環境で実行する
- 外注、有料SDK、有料バックエンド、新規有料開発ツールを利用しない
- Apple Developer Program等、App Store公開に必須のApple関連費用は本上限へ含めず、`D-012`で契約主体とともに別途判断する。`D-012`確定前に支出しない
- 広告費は開発費に含めず、Phase 0.5は`D-010`、Phase 2は`D-014`で別途判断する
- 週次および4週目に、経過週、累計責任者時間、残作業、未通過の品質Gate、外部待ち、残見積り、完了予測週、完了時総時間見込み（EAC）を記録する
- 4週目に目標8週間／224時間を超える見込みなら、価値・品質・計測を維持する回復策または実装簡素化案を作る。10週間／280時間を超える見込みなら8週目を待たず、新規実装を止めてHuman Ownerへ提示する
- 8週間または224時間の早い方に到達した時点で、残作業、品質Gate、10週間／280時間内の完了見込みを再予測する
- 10週間または280時間の早い方へ到達する前に作業を止め、MLPの価値連鎖を維持した実装簡素化・スコープ削減案、または上限変更案をHuman Ownerへ提示する。自動延長しない
- `D-005`でWon'tとしたAppleカレンダー連携、簡易共有、体験記録、ウィジェットはPhase 1中に追加しない

Phase 1開始日は、`P0-GATE-02`と`P05-GATE-01`通過後、最初のPhase 1 TaskをIn Progressへ変更し、Human Owner承認済みの開始日をGitHub Projectと週次記録へ残した日とする。Gate通過前の先行実装は行わず、Phase 1 Taskの準備・設計・実装を開始した時間を都合よく期間外へ移さない。

Apple審査等の外部待ちは責任者時間を消費しなくてもカレンダー上の経過として数え、週次報告する。反対に、集中稼働で280時間へ先に到達する場合も停止する。責任者時間には実装だけでなく、Product / Data / Legal / Validation / MarketingのPhase 1作業、レビュー、修正、公開準備を含める。

上限対応で`D-004`／`D-017`のMust、`D-002`／`D-003`の対象、`D-013`のコンテンツ品質、`D-007〜009`で固定する計測可能性、Legal / Privacy / App Storeの品質GateをAI判断で削らない。削減が必要な場合は、影響するD-IDとFrozen ScopeをHuman Ownerが改定する。上限到達時にGateが未達なら未完成のまま停止し、品質や計測を落として完了扱いにしない。

## 背景と制約

Phase 1はValidation Releaseを作るための検証投資であり、正式v1の全機能を完成させる段階ではない。`D-004`と`D-017`のMust、`D-005`のWon'tを開発前にFrozen Scopeへ固定し、限られた責任者稼働の中でコア体験と検証可能性を欠けさせずに完成させる必要がある。

## 検討した選択肢

| 選択肢 | 利点 | 欠点・リスク | 採否 |
|---|---|---|---|
| A：目標8週／224時間、上限10週／280時間、追加開発費0円 | 週28時間と整合し、目標と停止線を分離できる | 予期しない技術・審査問題ではスコープ再判断が必要 | 採用 |
| B：目標10週、上限12週 | 余裕を確保しやすい | Validation Releaseとして投資が膨らみ、Scope Creepを招きやすい | 不採用 |
| C：期間上限だけ固定し、責任者時間は固定しない | 管理が簡単 | 実投資量と前倒し余力の使途を管理できない | 不採用 |

## 根拠と不確実性

- 根拠：責任者は週28時間を確保でき、外注を行わず、既存AIサービスで推進する方針が確定している
- 根拠：目標8週は224時間、ハード上限10週は280時間で週次稼働と直接対応する
- 不確実性：`D-006`の技術選定、`D-007〜009`の計測要件、`D-011〜012`の配布・Apple要件が未確定であり、見積り精度は`P0-PROD-04〜05`で更新する必要がある
- 不確実性：Apple審査期間や外部サービス要件は責任者が制御できない
