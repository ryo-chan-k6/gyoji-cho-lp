# LINE公式アカウント運用セットアップ（フェーズ1・外部作業）

まいにち行事カレンダー 〜日本の行事帖〜（GYOJI-CHO）の需要検証向け。  
**アカウント開設・拡張ツール設定・チャットフロー実装・経路別リンク発行**は運営者（ユーザー）が行う作業です。本ドキュメントはその手順と原稿の確定版です。

LP側のURL投入は完了後に [`line-cta-setup.md`](line-cta-setup.md) を参照してください。

## 1. LINE公式アカウント開設

1. [LINE Official Account Manager](https://manager.line.biz/) でアカウント作成  
   - アカウント名（表示例）：`まいにち行事カレンダー`  
   - 業種：子育て・ライフスタイル系で近いものを選択  
   - 認証：検証初期は未認証で可（後から申請）
2. プロフィールを最低限埋める  
   - アイコン・カバー（なければLPと同系の単色＋ロゴでも可）  
   - 紹介文例：

     > 調べなくていい。赤ちゃんの行事、全部自動登録。  
     > 出産予定日を教えるだけで、お宮参り〜七五三の目安とミニコラムをお届けします。  
     > ※現在は事前登録・LINE配信のみ。アプリ本体は開発準備中です。

3. 応答モード  
   - L Message 接続後は **Bot**（またはエルメ推奨の設定）に合わせる  
   - 接続前の仮運用でも、あいさつメッセージを空にしない
4. プラン（当面）  
   - **コミュニケーション（無料）** で開始してよい  
   - 月間メッセージ通数が無料枠を超えそうになったらライト／スタンダードへ（下表「5. 料金試算」）

公式の友だち追加ガイド：  
https://www.lycbiz.com/jp/manual/OfficialAccountManager/gain-friends/

## 2. 拡張ツール：L Message（エルメ）無料プラン

### 選定理由（計画どおり）

| 観点 | 方針 |
|---|---|
| 検証フェーズ | **L Message フリープラン優先**（月1,000通・クレカ不要） |
| 必要機能 | チャット回答の**構造化保存**（出産予定日・性別・家族構成） |
| 代替 | 友だち数が増え、タグ／シナリオが足りなくなったら Lステップ等を再検討 |

公式：https://lme.jp/  
マニュアル（テンプレ／アクション）：https://lme.jp/manual/

### 導入手順（概要）

1. L Message にサインアップ（フリープラン）
2. LINE公式アカウントを連携（Messaging API チャネル作成 → チャネルアクセストークン等をエルメに登録）
3. LINE公式側のWebhook／応答設定をエルメ推奨どおりにする（二重応答に注意）
4. 無料枠の目安：エルメ配信 **月1,000通**。検証初期のステップ配信は「登録直後＋週1コラム」程度に抑える

### データ取得の推奨構成

検証初期は次のどちらか（または併用）で足りる。

| 方式 | 向いていること | 備考 |
|---|---|---|
| **クイックリプライ連鎖**（エルメアクション） | 性別・続柄など選択肢が少ない項目 | LPの「クイックリプライ形式」に合致 |
| **フォーム作成**（フリーでも作成可・上限あり） | 出産予定日・生年月日の入力 | 構造化保存・スプレッドシート連携向き |

**推奨**：あいさつ直後にフォーム1通（予定日／生年月日）→ 続けてクイックリプライで性別・続柄。

収集項目はプライバシーポリシーと一致させること：

- 出産予定日、またはお子さまの生年月日
- お子さまの性別
- 家族構成（続柄）

## 3. チャットフロー設計（実装用原稿）

```text
[友だち追加]
    ↓
[あいさつ + β注記 + 登録お願い]
    ↓
[Q1 出産予定日 or 生年月日] ← フォーム推奨
    ↓
[Q2 お子さまの性別] ← クイックリプライ
    ↓
[Q3 あなたの続柄] ← クイックリプライ
    ↓
[完了メッセージ + 最初の行事コラム]
    ↓
[ステップ配信：行事コラム（週1目安）]
```

### 3-1. 友だち追加時あいさつ

```text
はじめまして！「まいにち行事カレンダー 〜日本の行事帖〜」です🍼

調べなくていい。赤ちゃんの行事、全部自動登録——を目指して、いま事前登録を受け付けています。

【いまできること】
・お子さまの時期に合わせた行事の目安とミニコラムの配信
・アプリ正式リリース時の先行案内

※アプリ本体（自動カレンダー）は開発準備中です。現時点ではLINEでの情報配信のみとなります。

まずは、お子さまの出産予定日（または生年月日）を教えてください。
行事のご案内・サービス改善以外には使いません。
```

（ここでフォームURL、または「回答する」ボタン／次メッセージでQ1へ）

### 3-2. Q1 出産予定日／生年月日

**フォーム項目例**

| 項目 | 型 | 必須 |
|---|---|---|
| 状態 | 選択：妊娠中／出産済み | 必須 |
| 出産予定日 | 日付（妊娠中のとき） | 条件付き必須 |
| 生年月日 | 日付（出産済みのとき） | 条件付き必須 |

テキスト運用に落とす場合の誘導文：

```text
出産予定日、またはお子さまの生年月日を「YYYY/MM/DD」の形で送ってください。
例）2026/12/01
```

### 3-3. Q2 性別（クイックリプライ）

本文：

```text
ありがとうございます。
お子さまの性別を教えてください（わからない／答えたくない場合は「未定・その他」でOKです）。
```

ボタン：

| 表示 | タグ例 |
|---|---|
| 女の子 | `gender_girl` |
| 男の子 | `gender_boy` |
| 未定・その他 | `gender_other` |

### 3-4. Q3 続柄（クイックリプライ）

本文：

```text
最後に、あなたとお子さまの関係を教えてください。
```

ボタン：

| 表示 | タグ例 |
|---|---|
| ママ | `role_mama` |
| パパ | `role_papa` |
| 祖父母 | `role_grand` |
| その他家族 | `role_other` |

### 3-5. 完了メッセージ

```text
登録ありがとうございます！🎉

いただいた情報をもとに、行事の目安とミニコラムをお届けします。
配信が不要になったら、いつでもブロック／友だち解除で停止できます。

まずは一通目——「お宮参りって、いつごろ？」のミニコラムです。
```

### 3-6. 行事コラム（ステップ配信・初回セット）

検証初期は **3〜5本** で十分。配信間隔は **登録完了直後 → 3日後 → 7日後 → 以降週1** など。

| # | タイトル案 | ねらい |
|---|---|---|
| 1 | お宮参りって、いつごろ？ | 直後の関心が高い行事 |
| 2 | お食い初めの準備、何から？ | 生後100日前後の備え |
| 3 | 「それ、いつやるんだっけ？」をなくすには | サービス価値の再訴求 |
| 4 | 七五三は何歳から考える？ | 中期の行事意識 |
| 5 | アプリ開発のいま（β通信） | 期待維持・離脱防止 |

コラム本文は各400〜800字程度。毎回末尾に「返信不要／ブロックで配信停止可」を短く添える。

### 3-7. エルメ実装チェック（管理画面）

- [ ] 友だち追加時アクションにあいさつを設定
- [ ] Q1→Q2→Q3 のアクション連鎖（またはフォーム完了トリガー）
- [ ] 回答ごとにタグ付与（後のセグメント用）
- [ ] 完了後にシナリオ「行事コラム」を開始
- [ ] テスト用LINEアカウントで友だち追加〜コラム1通目まで確認
- [ ] 二重応答（公式の自動応答とエルメの競合）がないこと

## 4. 流入経路別友だち追加リンク

LPの `?ch=` と1対1対応させる。**必ず3本発行**し、発行直後に下表へ控える（公式の経路設定は後から一覧しづらい）。

### 4-A. LINE公式の「友だち追加経路」（必須・ベース）

PC版管理画面のみ。

1. ホーム → **友だちを増やす** → **友だち追加ガイド**
2. **友だち追加経路を設定** → 作成
3. 次の3経路を発行し、表示された **URL（lin.ee 等）** をコピー

| LPキー | 経路（必須・推奨値） | 流入元（任意） | キャンペーン（任意） | 控えるURL |
|---|---|---|---|---|
| `default` | `lp-default` | `organic` | `beta-prereg` | |
| `meta` | `lp-meta` | `meta-ads` | `beta-prereg` | |
| `google` | `lp-google` | `google-ads` | `beta-prereg` | |

公式分析の注意：期間内に経路あたり概ね20件未満だと詳細が「その他」にまとまることがある。少件数でもチャネル別CVRを見るなら、次の4-Bを併用する。

### 4-B. L Message の経路別リンク／パラメータ（推奨）

エルメ側でも流入経路用の友だち追加URL（またはパラメータ付きリンク）を発行できる場合は、**広告用はエルメ発行URLを優先**する。

- 1人から経路タグが付く（公式の「20件の壁」を回避）
- あいさつやリッチメニューの出し分けがしやすい

この場合も、LPの `LINE_CTA_CONFIG` に入れるのは **最終的にユーザーが開く友だち追加URL** でよい（公式URLでもエルメURLでも可）。重要なのは **meta / google / default で別URL** であること。

### 4-C. LP・広告への接続

発行後：

1. [`public/js/line-cta-config.js`](../public/js/line-cta-config.js) に3本を記入（手順は [`line-cta-setup.md`](line-cta-setup.md)）
2. `main` に push → **Cloudflare Pages** に反映（[`cloudflare-pages-setup.md`](cloudflare-pages-setup.md)）
3. 確認  
   - `https://gyoji-cho.pages.dev/?ch=meta`  
   - `https://gyoji-cho.pages.dev/?ch=google`  
   - Console で `__LINE_CTA_URL__` が想定どおり  
   - 実機で友だち追加〜フロー完走

広告のリンク先：

- Meta / Instagram: `https://gyoji-cho.pages.dev/?ch=meta`
- Google: `https://gyoji-cho.pages.dev/?ch=google`

（Pages のプロジェクト名が違う場合は、実際の `*.pages.dev` に読み替える。）

## 5. 料金プラン試算（検証規模）

### LINE公式アカウント（目安・税別）

| プラン | 月額目安 | 無料メッセージ／月 | 追加メッセージ |
|---|---|---|---|
| コミュニケーション | 0円 | 200通 | 不可（超過分は送れない） |
| ライト | 5,000円 | 5,000通 | 不可 |
| スタンダード | 15,000円 | 30,000通 | 従量（追加メッセージ） |

**2026年10月1日〜の追加メッセージ改定**（スタンダードの超過分・公式発表）：

- 〜20万通／月：1通 **3円**
- 20万通超：1通 **2.5円**

出典：https://www.lycbiz.com/jp/news/line-official-account/20260216/

### 検証フェーズの目安シナリオ

仮定例：友だち **200人**、登録直後に平均 **4通**（あいさつ＋Q＋完了＋コラム1）、その後月 **2通** のコラム。

| 項目 | 計算 | 結果 |
|---|---|---|
| 新規200人の初月オンボーディング | 200 × 4 | 800通 |
| 既存への月次コラム | 200 × 2 | 400通 |
| 合計（粗い上限） | | **約1,200通／月** |

→ 当面は **コミュニケーション or ライト** で足りる可能性が高い。  
→ エルメ無料枠（1,000通）より先に公式側の通数／エルメ枠のどちらが枯渇するか監視する。  
→ 一斉配信を増やしすぎない（セグメント・ステップで通数を抑える）。

### 運用メモ

- 検証中は「全員一斉」より **登録日起点のステップ** を優先
- 10月改定後も、月3万通以内なら追加メッセージ課金自体が発生しにくい（スタンダード想定）
- 友だちが数千規模・高頻度配信になる段階でスタンダード＋通数試算をやり直す
