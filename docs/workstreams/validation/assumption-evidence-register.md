## 使い方

本台帳は「正しいと信じること」の一覧ではなく、事業継続判断に影響する未検証仮説と、反対の結果を含めて必要な証拠を事前に整理するための正本である。

- 状態は `未検証 / 支持 / 棄却 / 不明` で管理する
- `支持`は仮説が永久に正しいことを意味せず、事前に定めた対象・期間・基準で必要証拠が得られた状態を指す
- KPI閾値、必要母数、at-risk開始、観測窓、打切日、不明条件は本台帳で決めず、`D-009`とProduct validation charterで事前固定する
- 広告反応、アプリ利用、定性発言、収益意向を相互の代替証拠として扱わない
- 結果取得後に反証条件を変更する場合は、逸脱として記録し責任者判断を求める

## 優先順位

- **Critical**：棄却された場合、MLP開発または事業の中心仮説を見直す
- **High**：体験、獲得、計測、将来収益の設計を大きく変える
- **Medium**：優先順位や表現を変えるが、中心仮説を単独では否定しない

同じ優先度では、不確実性が高く、より早いPhaseで低コストに反証できる仮説を先に検証する。Product Value全体は複数仮説を束ねて1つの状態にせず、`D-009`で定める構成仮説別の基準から判断する。

## 横断的なバイアス・欠測リスク

| リスク | 誤った解釈 | 事前に必要な対策 |
|---|---|---|
| 妊娠期コホートの生存者バイアス | 出生後まで残った人だけを分母にして、妊娠期流入の価値を過大評価する | 妊娠期流入全体→出生報告可能→出生情報更新→行事生成→Activation→Retentionの分母鎖を保持する |
| 妊娠期／出生後群の条件差 | 流入時期以外の差を、妊娠期獲得のRetention効果と解釈する | 流入チャネル、登録暦日・季節、出生後月齢、観測機会を層別・調整し、限界を明記する |
| 右側打ち切り | 実験終了までに対象行事、通知、D7 / D30等の観測機会を完了していない人を失敗扱いする | 指標ごとにat-risk開始、観測窓、打切日を定義し、未完了者を失敗分母から除外して不明を許す |
| 広告反応とProduct Valueの混同 | 高CTRを需要、低CTRをProduct不成立と解釈する | ChannelとProductの母集団・指標・判定を分ける |
| 通知の選択バイアス | 通知許可者だけの高Retentionを通知効果と解釈する | 許可→配信適格→配信成功→観測可能の分母を分け、比較設計なしに因果を断定しない |
| CTAクリックの意図誤認 | 情報確認クリックを購買意向と解釈する | 非クリック者も定性対象に含め、後続探索・離脱と組み合わせ、クリック単独で収益性を支持しない |
| 少数コホート | 月齢・季節・流入元を細分化し、偶然の差を結論にする | `D-009`で必要母数、統合条件、不明判定ルールを固定する |
